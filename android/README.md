# AirGrab — Android

## Toolchain

Android Studio is **not** installed and is not required. The IDE is roughly
10 GB of editor; building an APK needs only a JDK, the SDK and Gradle, which
come to about 2 GB. The IDE can be added later on top of this same SDK.

| Component | Version | Location |
|---|---|---|
| JDK | 17.0.13 | `%LOCALAPPDATA%\Programs\jdk17` |
| Android SDK | platform 36, build-tools 36.0.0 | `%LOCALAPPDATA%\Android\Sdk` |
| Gradle | 8.13 | `%LOCALAPPDATA%\Programs\gradle\gradle-8.13` |

Reinstall with `tools/install-android-sdk.sh`, `tools/install-android-packages.sh`
and `tools/install-gradle.sh` from the repository root.

## Building

```bash
export JAVA_HOME="C:/Users/PADMAP~1/AppData/Local/Programs/jdk17"
export ANDROID_HOME="C:/Users/PADMAP~1/AppData/Local/Android/Sdk"
GRADLE="$LOCALAPPDATA/Programs/gradle/gradle-8.13/bin/gradle.bat"

"$GRADLE" :core:test          # pure Kotlin, seconds, no device needed
"$GRADLE" :app:assembleDebug  # APK at app/build/outputs/apk/debug/
```

Install to a connected phone with
`%LOCALAPPDATA%\Android\Sdk\platform-tools\adb.exe install -r app-debug.apk`
(the device needs Developer Options and USB debugging enabled).

## Two Windows traps that cost real time

Both stem from this machine's user profile being `PADMA PRIYA`, with a space.

**1. `sdkmanager.bat` invokes `%JAVA_HOME%\bin\java` unquoted.** With a space in
the path, cmd splits the command and reports that `'C:\Users\PADMA' is not
recognized as an internal or external command`. Every package install fails
while appearing to run. The fix is the 8.3 short name `PADMAP~1`, which is the
same directory without a space.

**2. `local.properties` is a Java properties file, where `\` starts an escape
sequence.** A Windows path written with single backslashes is silently
mangled, and Gradle fails with `The filename, directory name, or volume label
syntax is incorrect` — which names neither the file nor the property. Write
`sdk.dir` with forward slashes; Java accepts them on Windows.

`local.properties` is gitignored because it is machine-specific. Recreate it as:

```properties
sdk.dir=C:/Users/PADMAP~1/AppData/Local/Android/Sdk
```

## Module layout

```
core/   plain Kotlin/JVM — no Android APIs at all
app/    the Android application, depends on :core
```

`core` is deliberately **not** an Android module. `Sas`, `GrabStateMachine` and
`GestureCoordinator` are ports of logic already proven in the Python
implementation and contain nothing Android-specific, so keeping them out of the
Android plugin means they compile and test in seconds on any JVM — no
emulator, no device, no SDK.

That is also what makes `SasVectorsTest` possible. It reads
`protocol/vectors/sas.json`, generated by the Python side, and fails the build
if this port ever computes a different pairing code. Without it, a drifting
implementation surfaces as two mismatched six-digit numbers on two screens with
nothing to indicate which side is wrong.

One trap the vectors caught by design: Kotlin's `Byte` is signed, so any digest
byte above `0x7F` sign-extends and corrupts the code unless masked back to
`0..255`. The Python cannot have this bug, so only a cross-language test finds it.

## Status

Built and passing: `core` (38 tests) and a debug APK that compiles and links
against it.

Not yet written: identity and the keystore, the trust store, the control
